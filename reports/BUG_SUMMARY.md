## 2. Prioritized Bug & Security Register

| Issue ID | Severity | Category | Title & Affected Module | Root Cause | Impact | Status | Verification & Resolution |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **SEC-001** | **Critical** | Auth / BOLA | Broken Access Control on Grievances (`complaintController.js`) | `getComplaintById` lacked role validation; any user guessing an ID could read complaints. | Confidential grievances leaked across roles. | **VERIFIED FIXED** | Added strict ownership checks: MENTEE owns, MENTOR assigned, ADMIN system-wide. |
| **SEC-002** | **Critical** | Security / Headers | Wildcard CORS & Missing Security Headers (`app.js`) | Express lacked security headers and accepted all cross-origin requests. | Potential Clickjacking, MIME-sniffing, and cross-site leaks. | **VERIFIED FIXED** | Injected hardened security headers (`X-Frame-Options`, `nosniff`, `HSTS`, `X-XSS-Protection`). |
| **SEC-003** | **Critical** | Security / Secrets | Plaintext Supabase DB Passwords & JWT Fallbacks (`env.js`) | Database URL fallback contained plaintext credentials and insecure JWT secret default in production. | Database compromise if `.env` omitted in deployment. | **VERIFIED FIXED** | Removed plaintext fallback; added strict boot validator requiring non-empty `DATABASE_URL` and secure `JWT_SECRET`. |
| **SEC-006** | **Critical** | Auth / Bypass | Known-Password Fallback Bypass in Authentication (`authController.js`) | `login` tested all default passwords (`Password@123`, `Student@2024`, `Mentor@2027`) if entered password was in the default list. | Attacker could use `Password@123` to access student accounts created with `Student@2024` or mentor accounts with `Mentor@2027`. | **VERIFIED FIXED** | Removed multi-fallback loop completely; authentication strictly compares supplied password against stored hash. |
| **SEC-007** | **Critical** | Security / Logs | Plaintext Admin Credential Logging (`server.js`, `env.js`) | `console.log` printed default master admin password in startup logs; hardcoded default password used. | Anyone with log access could read initial master admin password. | **VERIFIED FIXED** | Removed password logging; added `ADMIN_PASSWORD` to environment configuration; enforce `mustChangePassword: true`. |
| **SEC-013** | **Critical** | Auth / Fallback | Insecure Admin Password Fallback on Initial Boot (`server.js`, `env.js`) | `initialPassword = ENV.ADMIN_PASSWORD || 'Password@123'` created predictable admin in production if env was missing. | Predictable admin credential provisioned in production. | **VERIFIED FIXED** | Removed `'Password@123'` fallback. Server refuses to boot in production unless high-entropy `ADMIN_PASSWORD` (min 12 chars) is provided. |
| **SEC-018** | **Critical** | Auth / Credentials | Shared Default Passwords in Bulk Import (`bulkImportService.js`) | Bulk import provisioned all students with `Student@2024` and mentors with `Mentor@2027`. | Instant account takeover vulnerability upon batch user provisioning. | **VERIFIED FIXED** | Removed shared credentials. Implemented unique per-account cryptographically secure random temporary passwords (`base64url`, 24 bytes) hashed individually. |
| **TEST-004**| **Critical** | Test / Safety | Test Database Isolation Flaw & Broken Finally Cleanup (`test-*.js`, `test-db-guard.js`) | Test suites connected to `localhost:5001` without verifying server target DB, and `process.exit()` aborted `finally` fixture cleanup. | Live database mutation risk and orphaned test fixtures. | **VERIFIED FIXED** | Built deterministic DB fingerprinting and server isolation check; replaced `process.exit()` with `process.exitCode`; verified fixture cleanup in `finally`. |
| **SEC-004** | **High** | Auth / IDOR | IDOR in Coding Counter Verification (`weeklyTargetController.js`) | `updateCodingCounters` did not verify if target student belonged to mentor's assigned mentees or trainer's batch. | A mentor could falsify LeetCode verification numbers for any student in the college. | **VERIFIED FIXED** | Added strict scoped check: Mentors restricted to assigned mentees, Trainers to assigned batches, Mentees to self. |
| **SEC-005** | **High** | Auth / Access | Unprotected Mentee Profile Inspection (`userRoutes.js`, `roleMiddleware.js`) | `GET /mentees/:id` lacked batch-aware mentor/trainer scoping. | Any trainer or mentor could view details of arbitrary unassigned students. | **VERIFIED FIXED** | Enhanced `checkMentorMenteeAccess` middleware to support `TRAINER` batch membership. |
| **SEC-008** | **High** | Auth / Scope | Task Modification & Assignment Scope Bypass (`taskController.js`) | `updateTask` and `extendTaskDeadline` permitted any mentor to edit other mentors' or admin tasks; `assignTaskToRecipients` lacked ownership check. | Mentors could tamper with university-wide tasks or assign tasks outside their assigned roster. | **VERIFIED FIXED** | Enforced that only creator or admin can update, extend, or assign tasks; recipients restricted to mentor's mentees or trainer's batches. |
| **SEC-009** | **High** | Access / Progress | Cross-Mentor Task Progress & Mentee Task Inspection (`taskController.js`, `menteeTaskController.js`) | `getTaskProgress` and `getMenteeTaskById` lacked assignment and batch scoping. | Mentors could inspect task submissions and notes of students not assigned to them. | **VERIFIED FIXED** | Scoped progress and task inspection: mentors restricted to assigned mentees, trainers to assigned batches. |
| **SEC-010** | **High** | Auth / Review | Broken Access Control on Task Reviews (`reviewController.js`) | `getTaskReviewById` and `submitReview` lacked mentor assignment and trainer batch validation. | Any mentor or trainer could review, approve, or reject tasks of unassigned students. | **VERIFIED FIXED** | Injected ownership validation: review actions strictly restricted to assigned mentors, assigned trainers, or admins. |
| **SEC-011** | **High** | Access / Batch | Daily Problem Cross-Batch Information Disclosure (`trainerController.js`) | `getDailyProblemById` lacked batch authorization check. | Trainers and mentees could inspect problem details, company tags, and stats for unassigned batches. | **VERIFIED FIXED** | Added batch membership verification for trainers, mentees, and mentors; non-members receive HTTP 403 Forbidden. |
| **SEC-014** | **High** | Auth / Credential | Default Password Fallbacks in Account Creation (`userController.js`, `trainerController.js`) | Both controllers permitted omitting the password, silently falling back to `Password@123`. | Predictable credentials created for faculty and trainers. | **VERIFIED FIXED** | Removed default fallbacks; endpoints now reject missing or short passwords (< 8 chars) or `Password@123` with HTTP 400. |
| **SEC-015** | **High** | Auth / Access | Temporary Password Enforcement Gate (`authMiddleware.js`) | `mustChangePassword` was stored in database but never checked by middleware. | Users with temporary passwords accessed all functional application features without password rotation. | **VERIFIED FIXED** | In `authMiddleware`, newly provisioned users with `mustChangePassword: true` are blocked from all functional endpoints except `/auth/change-password`, `/auth/me`, and `/auth/logout`. |
| **SEC-016** | **High** | Security / CORS | Insecure CORS Domain Suffix Matching & Missing CSP (`app.js`) | Allowed localhost in prod, used `.endsWith('.sru.edu.in')` matching `evil-sru.edu.in`, and had no CSP header. | Cross-origin exploitation, clickjacking, and XSS vulnerabilities. | **VERIFIED FIXED** | Implemented exact URL parsing, required HTTPS in prod, validated exact hostname boundaries, added strict Content-Security-Policy (CSP), and added catch-all JSON 404 handler. |
| **SEC-019** | **High** | Auth / Seed | Unsafe Seed Password Fallback (`seedPrisma.js`, `seed.js`, `seedTrainerAndCalendar.js`) | Seeding scripts fell back to predictable `DevSeed@2026!` when `SEED_DEFAULT_PASSWORD` was unset. | Potential creation of known accounts with predictable passwords. | **VERIFIED FIXED** | Removed fallback; seed scripts fail safely unless explicit `SEED_DEFAULT_PASSWORD` (min 8 chars) is configured; seeded accounts set `mustChangePassword: true`. |
| **SEC-020** | **High** | Security / Privacy | Plaintext Password Exposure in Reset Response (`authController.js`) | `mentorResetMenteePassword` returned plaintext password in JSON message; allowed 6-character passwords. | Password leaked via API response payload and network logs. | **VERIFIED FIXED** | Enforced min 8 char policy; sanitized response to omit plaintext password string. |
| **SEC-021** | **High** | Security / CSP | Permissive Production CSP & Localhost Endpoints (`app.js`) | Production CSP `connect-src` contained localhost endpoints and `script-src` allowed `unsafe-inline`. | Broadened attack surface and violation of CSP defense-in-depth in production. | **VERIFIED FIXED** | Removed all localhost endpoints from production `connect-src`; removed `'unsafe-inline'` from production `script-src`. |
| **TEST-003**| **High** | Test / Safety | Automated Test Primary Database Mutation (`test-*.js`, `test-db-guard.js`) | Test suites connected directly to primary database, creating and deleting sections, tasks, and users. | Live data corruption during automated test runs. | **VERIFIED FIXED** | Implemented `test-db-guard.js` checking `TEST_DATABASE_URL` isolation. Mutating operations safely skip when running against unisolated database. |
| **BUG-001** | **High** | Business Logic | Unhandled `TRAINER` Role in Password Recovery (`authController.js`) | `forgotPassword` checked only `MENTOR` and `MENTEE`, leaving corporate trainers stranded on forgot password. | Trainers unable to reset passwords or contact administrators. | **VERIFIED FIXED** | Added explicit `TRAINER` recovery path with administrator notification and audit logging. |
| **BUG-002** | **High** | Access / Reports | Missing `TRAINER` Role in Reports & Unscoped Batch Reports (`reportRoutes.js`, `reportController.js`) | Report endpoints restricted strictly to `ADMIN` and `MENTOR`; trainer batches unhandled. | Trainers unable to export audit reports for assigned batches. | **VERIFIED FIXED** | Added `TRAINER` to allowed roles and scoped mentee/mock reports to trainer's assigned batches. |
| **SEC-012** | **Medium** | Security / Headers | Incomplete Security Headers & CORS Error Status (`app.js`) | Missing `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`. CORS rejections returned 500. | Reduced defense-in-depth and generic errors on blocked origins. | **VERIFIED FIXED** | Added full security header set; set explicit HTTP 403 status on CORS blocked origins. |
| **SEC-017** | **Medium** | Ops / Safety | Unprotected Database Seeding Scripts (`seedPrisma.js`, `seed.js`, `seedTrainerAndCalendar.js`) | Seeding scripts performed blanket deletions of 18 tables without checking for production environment. | Catastrophic loss of production records if seed script was triggered accidentally. | **VERIFIED FIXED** | Added fail-safe checks at the entry of all seed functions requiring `ALLOW_DESTRUCTIVE_SEED=true` to execute in production. |
| **PROD-002**| **Medium** | Reliability / Ops | Incomplete Graceful Shutdown & Production Error Information Leakage (`server.js`, `errorMiddleware.js`) | Shutdown did not disconnect Prisma pool; uncaught exceptions swallowed; error middleware leaked messages in 500. | Connection pool exhaustion on restarts; undefined process state; internal structure leaks. | **VERIFIED FIXED** | Enhanced shutdown with `prisma.$disconnect()`, watchdog timer, fatal uncaught exception termination, and masked 500 messages in production. |
| **TEST-002**| **Medium** | Testing | Lack of Automated Security Regression Suite (`test-security-regression.js`) | No automated tests validating cross-user isolation, task ownership, or credential fallback blocks. | Silent regressions on authorization rules during refactoring. | **VERIFIED FIXED** | Implemented `server/test-security-regression.js` with automated assertions; bound to `npm run test:security` and `npm test`. |
| **BUG-003** | **Medium** | Reliability / Health | Shallow Health Check Endpoint (`app.js`) | `/api/health` returned static `{ status: 'ok' }` without checking PostgreSQL database availability. | Load balancers route traffic to dead instances during DB downtime. | **VERIFIED FIXED** | Implemented deep health check running `SELECT 1` via Prisma. Returns HTTP 200 with DB status or HTTP 503. Exposes isolation fingerprint. |
| **BUG-004** | **Medium** | Test Suite | Static Past Dates in Mock Tests (`test-weekly-mocks.js`) | Automated tests used hardcoded `2026-10-20` dates which expired relative to current calendar date, failing partition checks. | Automated acceptance test suite failed during CI/CD. | **VERIFIED FIXED** | Converted slot scheduling in test suite to use dynamic future offsets (`today + 2 days`). |
| **BUG-005** | **Medium** | Test Suite | Obsolete Mentor Email in Bulk Import Suite (`test-bulk-import.js`) | Test used obsolete pre-migration email `mentor.alan@sru.edu.in`. | Test suite failed with HTTP 401 during authentication step. | **VERIFIED FIXED** | Updated credential to active SRU mentor `2303a51812@sru.edu.in`. |
| **BUG-006** | **Medium** | Dev Environment | Server Watcher Infinite Loop / Premature Terminations (`package.json`) | `node --watch src/server.js` watched entire `server/` directory, causing test scripts writing temporary files to reboot server mid-request. | `ECONNRESET` network dropouts during test runs. | **VERIFIED FIXED** | Scoped watcher explicitly to `--watch-path=src`. |
| **BUG-007** | **Low** | API Contracts | Invalid TargetType Enum & Counter Route Mismatch (`taskController.js`, `weeklyTargetRoutes.js`) | `createTask` threw validation error when `CUSTOM` targetType was passed; counter update route lacked `PUT`. | Task creation failure for individual assignments; counter update failures. | **VERIFIED FIXED** | Sanitized `CUSTOM` to `SELECTED` in `taskController`; enabled `PUT` on `/weekly-targets/counters`. |
| **PERF-001** | **Medium** | Performance | Oversized Single Bundle Chunk (`client/vite.config.js`) | Client built single monolithic 1.47 MB JavaScript bundle exceeding Vite recommendation. | Slower initial page load and poor Time to Interactive on low-bandwidth mobile devices. | **VERIFIED FIXED** | Configured Rolldown/Vite `manualChunks` function separating `vendor-react`, `vendor-charts`, `vendor-icons`, and `vendor-utils`. |
| **CONF-001** | **Low** | Configuration | Hardcoded API Base URL in Client Axios Service (`api.js`) | `baseURL: '/api/v1'` precluded cross-domain deployment (e.g. Vercel frontend + Render backend). | Deployment failure in decoupled CDN hosting environments. | **VERIFIED FIXED** | Configured `baseURL: import.meta.env.VITE_API_URL || '/api/v1'`. |
| **DEP-001** | **Low** | Dependencies | Dead Mongoose Schemas & Lingering Mongo Packages (`server/src/models/`, `package.json`) | Mongoose models remained after full migration to Prisma PostgreSQL. | Confusion for future maintainers and potential confusion on data layer. | **MITIGATED** | Documented Prisma ORM as canonical source of truth; marked legacy models for archival. |
| **INF-001** | **Low** | Code Quality | Unused Imports and Variables in Client Components (`oxlint`) | 275 lint warnings for unused variables in legacy page layouts. | Minor bundle overhead. | **DOCUMENTED** | Validated 0 linter errors; recommended scheduled cleanup. |
